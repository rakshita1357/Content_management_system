# TV Ads: Android TV app

A thin Android app around the **same `web-core/` page** the browser uses. No playback, sync or cache logic lives here:
the app is a full-screen `WebView` plus the things a browser tab cannot do on a TV.

| | Browser tab on the TV | This app |
|---|---|---|
| Opens when the ad server is down | No (the page comes from the server) | **Yes** (the page is inside the app; saved ads play) |
| Ads start with sound, no key press | No (browser blocks it) | **Yes** |
| Real full screen | Often not | **Yes**, system bars hidden |
| Screen stays awake | No | **Yes** |
| Starts when the TV switches on | No | Possible (see below) |
| Recovers from a crashed web engine | No | **Yes** (screen restarts) |
| Back key | Leaves the page | Leaves the player; never closes the app by accident |

The page is loaded from the app's own files under `https://tv.local/`, a secure origin, so IndexedDB (the offline cache) works
normally. Only `config.js` is generated by the app: it holds the ad server address.

## Build
Needs JDK 17 and the Android SDK (Android Studio installs both). From this folder:

```
./gradlew assembleDebug                                              # asks for the server address on the TV
./gradlew assembleDebug -Ptvads.defaultServer=http://192.168.1.20:8080   # or build the address in
```
The APK is `app/build/outputs/apk/debug/app-debug.apk`. The build copies `../../web-core` into the app, so **rebuild the app
after changing `web-core/`**. Run the address-parsing tests with `./gradlew test`.

## Install on the TV
1. On the TV: Settings → Device Preferences → About → tap *Build* seven times; then Developer options → enable *USB debugging* / *Network debugging*.
2. On your computer: `adb connect <tv-ip>:5555`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
3. Open **TV Ads** from the TV's app row.

First start (when no address was built in): a box asks for the **ad server address**, for example `192.168.1.20:8080` (the address the backend prints
as "Open this on the TV"). It is remembered. Change it later with the **Server address** button on the details screen. Choosing the Drive folder is
still done on a computer, on the backend's front page (or from the TV with *Change Drive folder*, which asks for the admin login).

## Starting when the TV switches on
The app listens for the boot broadcast and opens itself. Android 10 and newer only allow that for apps that may "display over other apps":

```
adb shell appops set com.tvads.player SYSTEM_ALERT_WINDOW allow
```
Some TV makers add their own limits (battery savers, "autostart" lists, or no boot broadcast at all); on those, set the app as the TV's
start-up / home app if the TV offers it. This depends on the TV model, so check it on yours.

## Network and security
- The backend is usually plain `http` on the local network. The app allows that (cleartext + mixed content) and only opens its own page and the configured ad server in its window; other addresses are blocked.
- For anything beyond a trusted local network, put the backend behind https and enter an `https://` address.
- Release builds need your own signing key (`keytool -genkey ...`, then a `signingConfig`); debug builds are signed with the debug key and are fine for your own TVs.

## What has and has not been checked
Checked: the Java sources compile against the Android 14 framework classes; the address parsing has unit tests; the page's hooks for this app
(Back handling, Server address button) are covered by the browser tests in `tv-ad-backend`.
**Not checked: a Gradle/Android Studio build, and running on a real Android TV or emulator.** The first build on a normal machine may need small fixes
(for example a newer Android Gradle Plugin version in `build.gradle`).
